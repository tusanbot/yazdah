# یازده (Yazdah)

بازی آنلاین مدیریت باشگاه فوتبال با رابط ربات تلگرام و Telegram Mini App؛ هر دو رابط به یک هستهٔ بازی، API و حساب کاربری مشترک متصل می‌شوند.

## اصول پروژه

- توسعه از صفر و به‌صورت مرحله‌ای؛ قابلیت‌ها باید عملیاتی باشند، نه صرفاً نمایشی.
- Supabase/PostgreSQL مستقل به‌عنوان پایگاه دادهٔ اصلی؛ بدون Prisma و Hyperdrive.
- تمام منطق حساس بازی و اعتبارسنجی‌ها در سمت سرور اجرا می‌شوند.
- تمام قابلیت‌های اصلی از هر دو رابط در دسترس‌اند.
- تراکنش‌های مالی و انتقال مالکیت باید اتمیک، قابل‌ردیابی و مقاوم در برابر اجرای تکراری باشند.
- رابط فارسی و راست‌چین با نمایش تاریخ شمسی؛ زمان‌ها در سرور به‌صورت استاندارد ذخیره می‌شوند.

## دامنهٔ هستهٔ بازی

باشگاه و پروفایل، بازیکنان، ترکیب و تاکتیک، آکادمی جوانان، امکانات باشگاه، کادر باشگاه، نقل‌وانتقالات بازیکنان، اقتصاد و دفترکل، موتور مسابقه، لیگ‌ها و جام‌ها، مأموریت‌ها و رویدادها، چالش‌ها و رقابت‌های گروهی تلگرام، اتحادیه‌ها، اعلان‌ها و پنل مدیریت.

**آکادمی** بخشی از مدیریت باشگاه است. **جذب کادر** در بخش نقل‌وانتقالات قرار می‌گیرد اما از نقل‌وانتقالات بازیکنان جداست و شامل کادر فنی، کادر پزشکی، بدنساز و مدیر نقل‌وانتقالات می‌شود.

## شروع توسعه

نقشهٔ معماری و تصمیم‌های فنی در `docs/architecture.md` ثبت می‌شوند. توسعه باید با مدل دامنه و قواعد امنیتی آغاز شود و سپس به API، ربات و Mini App برسد.


## اتصال گروه تلگرام

برای اتصال گروه، ربات باید در گروه حضور داشته باشد و اجازهٔ دریافت/ارسال پیام و بررسی اعضا را داشته باشد. مالک یا مدیر گروه دستور `/group` را در همان گروه اجرا می‌کند. ربات نقش مدیر را از Telegram دریافت می‌کند و API با راز داخلی مشترک، کاربر ثبت‌شده و مالکیت باشگاه را بررسی کرده و سپس گروه را ثبت می‌کند.

تنظیمات لازم برای این جریان:

- `YAZDAH_API_URL`: آدرس پایهٔ API برای ربات.
- `BOT_INTERNAL_SECRET`: راز تصادفی و طولانی مشترک بین سرویس ربات و API؛ باید فقط در محیط‌های سرور تنظیم شود و نباید در Mini App یا کد کلاینت قرار گیرد.
- `TELEGRAM_BOT_TOKEN`: توکن ربات که از قبل برای API و ربات لازم است.

این جریان هنوز به تست یکپارچه نیاز دارد؛ پیش از استفادهٔ عملی، هر دو سرویس باید با همین راز مشترک پیکربندی شوند.
